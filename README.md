# Lab 1 — A box of bytes (`ember`)

У першій лабораторній роботі я працював з байтами, типами даних і простою моделлю пам'яті.

`ember` має 4096 байтів пам'яті. Одна клітинка представлена типом `std::uint8_t`, тому може зберігати значення від 0 до 255. Допустимі адреси пам'яті — від 0 до 4095.

У ході роботи я реалізував читання і запис байтів, ASCII-колонку для `dump`, виведення одного байта у різних представленнях та команду `inc`. Також провів експерименти з переповненням, числами з рухомою комою, C-рядком і неініціалізованою пам'яттю.

---

# M1 — збірка і запуск

Спочатку я перевірив, що проєкт збирається і запускається.

Проєкт використовує C++17. У `CMakeLists.txt` також увімкнені попередження:

```txt
-Wall -Wextra -Werror
```

У Debug-збірці під Linux використовуються:

```txt
-fsanitize=address,undefined
```

тобто AddressSanitizer та UndefinedBehaviorSanitizer.

Для перевірки Debug-збірки я використовував WSL:

```bash
cmake -S . -B build-wsl -DCMAKE_BUILD_TYPE=Debug
cmake --build build-wsl
./build-wsl/ember
```

Після запуску програма виводить:

```txt
ember 0.1 - 4096 bytes of memory you can see. Type `help`.
ember>
```

`ember>` — це prompt програми. Після нього можна вводити команди `dump`, `get`, `set`, `inc`, `help` і `quit`.

Основна обробка команд знаходиться у `main.cpp`. Програма читає введений рядок, отримує з нього назву команди і через ланцюжок `if / else if` вибирає потрібну дію.

Наприклад:

```txt
dump
```

викликає функцію `dump(mem)`, а

```txt
get 0
```

читає байт з пам'яті та передає його у `show_byte`.

# M2 — пам'ять і `dump`

Пам'ять описана у `memory.hpp`:

```cpp
using Byte = std::uint8_t;

const std::size_t MEM_SIZE = 4096;

struct Memory {
    Byte data[MEM_SIZE]{};
};
```

`Byte` є короткою назвою для `std::uint8_t`.

Я використовую саме `std::uint8_t`, тому що одна клітинка `ember` повинна бути одним 8-бітним байтом. Її значення знаходиться в межах від 0 до 255.

`MEM_SIZE = 4096` означає, що пам'ять має 4096 клітинок. Оскільки індексація масиву починається з нуля, допустимі адреси:

```txt
0 ... 4095
```

Фігурні дужки у:

```cpp
Byte data[MEM_SIZE]{};
```

нуль-ініціалізують весь масив.

Тому після свіжого запуску я виконав:

```txt
ember> dump
```

Перші три рядки:

```txt
0000  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

Це показує, що після запуску всі байти пам'яті дорівнюють нулю.

`dump` показує по 16 байтів у кожному рядку.

Ліворуч знаходиться адреса початку рядка у hex, посередині — самі байти у hex, а праворуч — ASCII-представлення.

Для ASCII-колонки я реалізував перевірку:

```cpp
static bool is_printable(Byte b) {
    return b >= 0x20 && b <= 0x7E;
}
```

Якщо байт знаходиться в діапазоні друкованих ASCII-символів `0x20–0x7E`, виводиться сам символ. Інші значення показуються крапкою.

# M3 — читання і запис байта

На цьому етапі я реалізував `mem_get`, `mem_set` і `show_byte`.

## `mem_get`

```cpp
Byte mem_get(const Memory& mem, std::size_t addr) {
    if (addr >= MEM_SIZE) {
        return 0;
    }

    return mem.data[addr];
}
```

Функція читає байт за заданою адресою.

Перед читанням перевіряється:

```cpp
addr >= MEM_SIZE
```

Якщо адреса дорівнює 4096 або більша, вона знаходиться за межами пам'яті, тому функція не звертається до масиву і повертає 0.

Якщо адреса правильна, повертається:

```cpp
mem.data[addr]
```

---

## `mem_set`

```cpp
bool mem_set(Memory& mem, std::size_t addr, Byte value) {
    if (addr >= MEM_SIZE) {
        return false;
    }

    mem.data[addr] = value;
    return true;
}
```

Функція записує `value` у потрібну адресу.

Якщо адреса неправильна, повертається `false`, а пам'ять не змінюється.

Якщо запис успішний, повертається `true`.

Перевірка:

```txt
ember> set 5000 1
address 5000 is outside 0..4095
```

Програма не падає і не намагається записати значення за межами масиву.

---

## `show_byte`

Команда `get` показує один байт чотирма способами.

Перевірка:

```txt
ember> set 0 65
ember> get 0
65  0x41  0b01000001  'A'
```

Тут показано одне й те саме значення:

```txt
65          — десяткове представлення
0x41        — шістнадцяткове представлення
0b01000001  — двійкове представлення
'A'         — символ ASCII
```

Тобто `65`, `0x41`, `01000001` і `'A'` — це не різні значення, а різні способи представити одні й ті самі біти.

Для двійкового виводу використовується зсув і маска:

```cpp
for (int i = 7; i >= 0; --i) {
    std::cout << ((b >> i) & 1);
}
```

`b >> i` зсуває потрібний біт вправо, а `& 1` залишає тільки його значення — 0 або 1.

# M4 — експерименти

На M4 я провів чотири окремі експерименти.

## 1. Переповнення `uint8_t`

Я записав максимальне значення байта:

```txt
ember> set 0 255
ember> get 0
255  0xff  0b11111111  '.'
```

Потім використав команду `inc`, яка читає байт, додає одиницю та записує результат назад:

```txt
ember> inc 0
ember> get 0
0  0x00  0b00000000  '.'
```

`std::uint8_t` має тільки 8 бітів, тому максимальне значення — 255.

Після збільшення 255 значення загортається до 0.

Для беззнакового типу це визначена поведінка.

### Порівняння зі signed `int`

Окремо я перевірив переповнення знакового `int` через UBSan.

Отримав:

```txt
runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
```

На відміну від unsigned-типів, переповнення signed `int` у C++ є undefined behaviour, тому стандарт не гарантує конкретний результат.

---

## 2. `0.1 + 0.2`

У тесті я отримав:

```txt
0.3
false
```

На екрані сума виглядає як `0.3`, але перевірка:

```cpp
0.1 + 0.2 == 0.3
```

повернула `false`.

Причина в тому, що багато десяткових дробів неможливо точно представити у скінченному двійковому вигляді. Через це `float` і `double` можуть зберігати дуже близьке, але не абсолютно точне значення.

---

## 3. C-рядок `"AB"`

Я записав у пам'ять:

```txt
ember> set 0 65
ember> set 1 66
ember> set 2 0
ember> dump
```

Отримав:

```txt
0000  41 42 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |AB..............|
```

У пам'яті знаходяться:

```txt
65 66 0
```

або як символи:

```txt
A B \0
```

Нульовий байт `\0` завершує C-рядок, тому ці дані можна розглядати як рядок:

```txt
"AB"
```

У ASCII-колонці нуль показаний крапкою, оскільки він не є друкованим символом.

---

## 4. Експеримент без `{}`

Спочатку масив оголошений так:

```cpp
Byte data[MEM_SIZE]{};
```

Для експерименту я тимчасово прибрав `{}`:

```cpp
Byte data[MEM_SIZE];
```

Після перебудови програми виконав `dump`.

У моєму запуску перші байти все одно виглядали нульовими:

```txt
0000  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

Але це не означає, що без `{}` пам'ять гарантовано занулена.

Без ініціалізації початкові значення не гарантуються, а читання неініціалізованих даних може призвести до undefined behaviour.

Після експерименту я повернув `{}` назад.

# Notes §1 — `sizeof`

Я перевірив розміри основних типів на своєму комп'ютері.

Результат:

```txt
1 4 4 8 8
1 2
```

На моїй системі це означає:

| Тип | Розмір |
|---|---:|
| `char` | 1 байт |
| `int` | 4 байти |
| `float` | 4 байти |
| `double` | 8 байтів |
| вказівник | 8 байтів |
| `std::uint8_t` | 1 байт |
| `std::uint16_t` | 2 байти |

Цей експеримент показує, що різні типи займають різну кількість пам'яті.

Для клітинки `ember` використовується `std::uint8_t`, тому що для моделі потрібен саме один 8-бітний байт, а не звичайний `int`.

# Notes §4 — представлення значень і ділення

Ще один тест дав:

```txt
65 65 65 A
B
2 2.5
```

`65`, `0x41` і `'A'` можуть представляти одне й те саме значення.

При:

```cpp
'A' + 1
```

отримуємо символ `B`, тому що код `A` дорівнює 65, а код `B` — 66.

Також:

```cpp
5 / 2
```

дає:

```txt
2
```

тому що обидва операнди є цілими числами.

А:

```cpp
5 / 2.0
```

дає:

```txt
2.5
```

тому що `2.0` має тип з рухомою комою.

# Перевірка команд

Основні команди програми:

```txt
dump              — показати всі 4096 байтів
get <addr>        — показати один байт у dec / hex / bin / char
set <addr> <val>  — записати значення у пам'ять
inc <addr>        — збільшити байт на 1
help              — список команд
quit              — завершити програму
```

Перевірка виходу за межі:

```txt
ember> set 5000 1
address 5000 is outside 0..4095

ember> inc 5000
address 5000 is outside 0..4095
```

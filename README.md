# Lab 1 - ember

У цій лабораторній я працював з байтами, типами даних і пам’яттю.

Після запуску програма має такий вигляд:

```txt
ember 0.1 - 4096 bytes of memory you can see. Type `help`.
ember>
```

## sizeof

На моєму ПК вийшло:

```txt
1 4 4 8 8
1 2
```

Тобто char займає 1 байт, int - 4, float - 4, double - 8, вказівник - 8, uint8_t - 1 байт, uint16_t - 2 байти.

## get і set

```txt
ember> set 0 65
ember> get 0
65  0x41  0b01000001  'A'
```

Одне значення виводиться у десятковому, hex, двійковому вигляді і як символ.

## dump

```txt
ember> set 0 65
ember> set 1 66
ember> set 2 0
ember> dump
0000  41 42 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |AB..............|
0010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
```

65 - це символ A, 66 - B, а 0 завершує рядок.

## Перевірка меж пам’яті

```txt
ember> set 5000 1
address 5000 is outside 0..4095

ember> inc 5000
address 5000 is outside 0..4095
```

Пам’ять має 4096 байтів, тому адреси більші за 4095 не приймаються.

## Переповнення байта

```txt
ember> set 0 255
ember> get 0
255  0xff  0b11111111  '.'
ember> inc 0
ember> get 0
0  0x00  0b00000000  '.'
```

Після 255 для uint8_t значення стало 0.

Для int перевірив через UBSan:

```txt
runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
```

## 0.1 + 0.2

```txt
0.3
false
```

На екрані виходить 0.3, але точне значення в пам’яті трохи відрізняється, тому порівняння з 0.3 дає false.

## Експеримент без {}

Тимчасово прибрав {} з:

```cpp
Byte data[MEM_SIZE]{};
```

Після цього dump у моєму випадку все одно показав нулі, але без {} початкові значення не гарантуються. Після перевірки {} повернув назад.

## Чому uint8_t

Я використовую std::uint8_t, бо він займає рівно 1 байт і має значення від 0 до 255. Для моделі пам’яті це підходить краще, ніж int.

# Lab 02 - Біти не брешуть: системи числення, прапорці й ALU (`ember`)

У другій лабораторній роботі я продовжив проєкт `ember`, який був створений у Lab 01. У першій лабораторній уже була готова пам'ять на 4096 байтів і команди `dump`, `get`, `set`, `inc`, `help` та `quit`. У Lab 02 до цієї основи додається простий процесор, який читає інструкції з пам'яті та виконує їх по одній через команду `step`.

Основна тема цієї лабораторної - двійкова і шістнадцяткова системи, бітові операції, маски, зсуви, прапорці `Z`, `N`, `C` та розбір опкода. У результаті до `ember` були додані регістри `A` і `B`, лічильник команд `PC`, ALU, команди `reg`, `regs`, `step` і виконання інструкцій із пам'яті.

# Notes

Перед основною частиною Lab 02 я виконав досліди з Notes. Вони потрібні для окремої перевірки роботи з бітами, типами, масками, зсувами та перенесенням, а потім ті самі принципи використовуються вже в самому `ember`.

## §1 - hex і binary

Для значення:

```txt
0xA3
```

програма вивела:

```txt
a3
10100011
```

Шістнадцяткове число складається з двох частин:

```txt
A = 1010
3 = 0011
```

Отже:

```txt
0xA3 = 10100011
```

Цей дослід показує, як один байт можна представити у шістнадцятковому і двійковому вигляді.

## §2 - two's complement

У другому досліді я перевірив різницю між `int8_t` та `uint8_t`.

Результат:

```txt
-5
-6
250
```

Також одна й та сама бітова послідовність може мати різне значення залежно від типу. Наприклад, `0xFF` для `uint8_t` означає `255`, а для `int8_t` - `-1`.

---

## §3 - маски і зсуви

Для байта:

```txt
10111001
```

поля дістаються через маски і зсуви:

```cpp
opcode = (ins >> 4) & 0x0F;
dest   = (ins >> 2) & 0x03;
src    = ins & 0x03;
```

Результат:

```txt
11 2 1
```

Операція `>>` зсуває потрібні біти вправо, а маска `&` залишає тільки потрібну частину. Цей самий принцип далі використовується в `decode()` у `cpu.cpp`.

---

## §4 - пріоритет операторів

Перевірив різницю між:

```cpp
x & 1 == 0
```

та:

```cpp
(x & 1) == 0
```

Без дужок вираз може обчислюватися не так, як очікується через пріоритет операторів. Тому при роботі з масками використовую явні дужки.

---

## §5 - ADD по бітах

Для:

```txt
200 + 100
```

було отримано:

```txt
44 1 44
```

Тобто:

```txt
result = 44
carry = 1
```

Математично `200 + 100 = 300`, а `300 = 256 + 44`, тому в 8 бітах залишається `44`, а перенесення зберігається окремо. Побітове додавання збіглося з `uint8_t(a + b)`.

# M1 - ALU і прапорці

На першому етапі основної частини я додав ALU. Для цього були створені:

```txt
src/alu.hpp
src/alu.cpp
```

У `alu.hpp` оголошені функції, а в `alu.cpp` знаходиться їх реалізація.

Реалізовані операції:

```txt
ADD
SUB
AND
OR
XOR
NOT
SHL
SHR
INC
DEC
```

Усі вони працюють з типом `Byte`, який у проєкті є короткою назвою для `std::uint8_t`.

## Прапорці

ALU також оновлює прапорці `Z`, `N`, `C`.

- `Z = 1`, якщо результат операції дорівнює нулю.
- `N = 1`, якщо старший біт результату дорівнює 1.
- `C` використовується для перенесення, позики або біта, який вийшов за межі байта.

Для `ADD` прапорець `C` показує перенесення за межі 8 біт, для `SUB` - позику, а для `SHL` і `SHR` - біт, який вийшов за межі байта.

---

## Приклад 1 - ADD з перенесенням

Для перевірки:

```txt
A = 200
B = 100
```

Математично:

```txt
200 + 100 = 300
300 = 256 + 44
```

Один байт зберігає значення від `0` до `255`, тому в `A` залишається `44`, а `C` стає рівним `1`.

Результат:

```txt
A = 44
Z = 0
N = 0
C = 1
```

Перевірка в `ember`:

```txt
reg a 200
reg b 100
set 0 0x10
set 1 0x00
step
regs
```

Отримав:

```txt
PC=1 A=44 B=100 Z=0 N=0 C=1
```

---

## Приклад 2 - SHL з перенесенням

Для другого прикладу:

```txt
A = 200
```

У двійковому вигляді:

```txt
11001000
```

Після `SHL`:

```txt
10010000
```

Старший біт початкового числа виходить за межі байта, тому:

```txt
A = 144
Z = 0
N = 1
C = 1
```

`N = 1`, тому що старший біт нового результату дорівнює 1, а `C = 1`, бо один біт вийшов за межі байта.

# M2 - CPU, `regs` і `step`

На другому етапі до проєкту був доданий процесор.

Для цього використовуються:

```txt
src/cpu.hpp
src/cpu.cpp
```

`cpu.hpp` був даний у завданні. У ньому знаходяться коди операцій, структура `Flags`, структура `CPU`, а також оголошення `step()` і `dump_regs()`.

CPU містить регістри `A` і `B`, лічильник команд `PC`, прапорці `Z`, `N`, `C` та стан `halted`. `PC` зберігає адресу інструкції, яка буде виконана наступною.

## Команди

Команда `reg` записує значення в регістр:

```txt
reg a 200
reg b 100
```

Команда `regs` показує стан CPU:

```txt
PC=0 A=200 B=100 Z=0 N=0 C=0
```

Команда `step` виконує одну інструкцію з пам'яті за адресою `PC`.

---

## Перевірка ADD + HALT

У пам'ять записано:

```txt
set 0 0x10
set 1 0x00
```

Тут `0x10` - це `ADD A, B`, а `0x00` - `HALT`.

Перед виконанням:

```txt
PC=0 A=200 B=100 Z=0 N=0 C=0
```

Після першого `step`:

```txt
PC=1 A=44 B=100 Z=0 N=0 C=1
```

Після другого `step` виконується `HALT`:

```txt
PC=2 A=44 B=100 Z=0 N=0 C=1
```

Наступний виклик `step` вже не виконує інструкції та виводить:

```txt
halted
```

# M3 - програма в пам'яті

На третьому етапі я перевірив виконання програми, записаної в пам'ять через `set`.

Для `AND` використав:

```txt
reg a 7
reg b 1
set 0 0x12
set 1 0x00
```

`0x12` - це `AND A, B`.

У двійковому вигляді:

```txt
7 = 00000111
1 = 00000001
```

Операція:

```txt
    00000111
AND 00000001
-------------
    00000001
```

Тому після `step`:

```txt
PC=1 A=1 B=1 Z=0 N=0 C=0
```

# M4 - `decode()` і розбір опкода

На четвертому етапі я реалізував розбір опкода через маску і зсув.

Опкод ділиться на:
- старший півбайт - групу;
- молодший півбайт - індекс.

Група:

```cpp
group = (op >> 4) & 0x0F;
```

Індекс:

```cpp
index = op & 0x0F;
```

Наприклад:

```txt
0x12
```

дає:

```txt
group = 1
index = 2
```

Тобто `0x1_` - група ALU, а індекс `2` - `AND`. Отже `0x12 = AND A, B`.

Такий розбір дозволяє спочатку визначити групу інструкції, а вже потім конкретну операцію всередині цієї групи.

---

# Реалізовані інструкції ISA

У Lab 02 реалізовані групи `0x0_` і `0x1_`.

| Опкод | Інструкція | Дія |
|---|---|---|
| `0x00` | `HALT` | зупиняє процесор |
| `0x01` | `NOP` | нічого не змінює |
| `0x10` | `ADD A, B` | `A = A + B` |
| `0x11` | `SUB A, B` | `A = A - B` |
| `0x12` | `AND A, B` | `A = A & B` |
| `0x13` | `OR A, B` | `A = A | B` |
| `0x14` | `XOR A, B` | `A = A ^ B` |
| `0x15` | `NOT A` | `A = ~A` |
| `0x16` | `SHL A` | зсув `A` вліво |
| `0x17` | `SHR A` | зсув `A` вправо |
| `0x18` | `INC A` | `A = A + 1` |
| `0x19` | `DEC A` | `A = A - 1` |

Власних інструкцій у Lab 02 я не додавав.
